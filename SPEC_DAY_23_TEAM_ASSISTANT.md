# Спецификация: Командный ассистент (День 23)

## Обзор

Командный ассистент, интегрирующий RAG (знание проекта) и MCP (работа с файлами/Git) для управления задачами и анализа статуса проекта.

### Интеграция с существующей системой

- **RAG**: Используется для поиска информации в документации проекта (через Chunkenizer)
- **MCP Filesystem**: Чтение/запись файла задач `todo.md`
- **MCP Git**: Получение контекста о состоянии репозитория для `/status`

## Формат хранения задач

### Файл: `todo.md`

Все задачи хранятся в одном файле в корне проекта.

### Структура задачи (компактный формат)

```markdown
## [high] Fix authentication bug (id:a1b2c3d4, @alex, due:2024-01-20)

Description of the task goes here.
Can be multiline.

## [medium] Add unit tests (id:e5f6g7h8, @maria, status:in_progress)

More tests for the auth module.

## [low] Update README (id:i9j0k1l2, @alex, status:done)

Add installation instructions.
```

### Поля задачи

| Поле | Обязательность | Формат | Пример |
|------|----------------|--------|--------|
| title | Обязательно | Текст | `Fix authentication bug` |
| id | Авто | 8 символов hex | `a1b2c3d4` |
| priority | Обязательно | `high` / `medium` / `low` | `high` |
| assignee | Обязательно | `@username` | `@alex` |
| status | Опционально | `todo` / `in_progress` / `done` | `in_progress` |
| deadline | Опционально | `YYYY-MM-DD` | `2024-01-20` |
| description | Опционально | Markdown после заголовка | (многострочный текст) |

### Парсинг заголовка

Формат: `## [priority] Title (id:xxx, @assignee, due:YYYY-MM-DD, status:xxx)`

Регулярное выражение для парсинга:
```regex
^## \[(?P<priority>high|medium|low)\] (?P<title>.+?) \(id:(?P<id>[a-f0-9]{8})(?:, @(?P<assignee>\w+))?(?:, due:(?P<deadline>\d{4}-\d{2}-\d{2}))?(?:, status:(?P<status>todo|in_progress|done))?\)$
```

## Команды

### `/tasks` — Список задач

**Вызов**: `/tasks` или `/tasks high` или "покажи задачи"

**Поведение**:
1. Читает `todo.md` через MCP filesystem
2. Парсит все задачи
3. Фильтрует по параметрам (если указаны)
4. Выводит в формате Markdown-списка

**Формат вывода**:
```markdown
- [ ] Fix authentication bug (high, @alex, due: 2024-01-20)
- [x] Add unit tests (medium, @maria, in_progress)
- [x] Update README (low, @alex, done)
```

**Пустой список**: Ответ "Задач нет" (без предложений создать)

---

### `/add` — Создание задачи

**Вызов**: `/add Fix bug @alex high` или "создай задачу..."

**Обязательные поля при создании**:
- title
- priority
- assignee

**Поведение**:
1. Парсит запрос (извлекает title, priority, assignee, deadline)
2. Генерирует уникальный ID (8 символов hex)
3. Если deadline указан в прошлом — предупредить, но создать
4. Добавляет задачу в конец `todo.md`
5. Подтверждает создание

**Генерация ID**:
```python
import secrets
task_id = secrets.token_hex(4)  # "a1b2c3d4"
```

**Пример ответа**:
```
Задача создана:
- [ ] Fix bug (id:a1b2c3d4, high, @alex)
```

---

### `/status` — Сводка проекта

**Вызов**: `/status` или "как дела с проектом?"

**Поведение**:
1. Читает `todo.md` — считает статистику
2. Вызывает MCP Git — получает ветку, последние коммиты, измененные файлы
3. Анализирует риски (просроченные задачи, близкие дедлайны)
4. Формирует сводку

**Формат вывода**:
```markdown
## Статус проекта

**Задачи:**
- Todo: 5
- In progress: 2
- Done: 8

**Git:**
- Ветка: feature/auth
- Последний коммит: "Add login endpoint" (2 часа назад)
- Измененные файлы: 3

**Риски:**
⚠️ 2 задачи просрочены
⚠️ 1 задача с дедлайном завтра
```

---

### `/priority` — Рекомендации

**Вызов**: `/priority` или "что делать первым?"

**Поведение**:
1. Читает `todo.md`
2. Читает документацию проекта через RAG (блокеры, зависимости)
3. Сортирует по: priority → deadline → контекст RAG
4. Выводит топ-3 задачи

**Формат вывода** (простой нумерованный список):
```markdown
1. Fix authentication bug (@alex, due: завтра)
2. Add unit tests (@maria, high priority)
3. Update API docs (@alex, medium priority)
```

## Обработка изменений задач

### Поиск задачи

При запросе типа "закрой задачу про авторизацию":
1. **Fuzzy search** по title и description
2. Если найдено несколько — спросить уточнение
3. Если не найдено — сообщить об ошибке

### Изменение статуса

Естественным языком:
- "Закрой задачу X" → status: done
- "Начни работу над X" → status: in_progress
- "Верни X в todo" → status: todo

### Удаление задачи

**Требует подтверждения**:
```
Пользователь: Удали задачу про README
Ассистент: Вы уверены, что хотите удалить задачу "Update README" (id:i9j0k1l2)?
Пользователь: Да
Ассистент: Задача удалена.
```

## Конфликты и ошибки

### Last Write Wins

При одновременном редактировании несколькими пользователями — последнее изменение перезаписывает предыдущее. Система не отслеживает версии.

### Ошибки MCP

При ошибках записи/чтения файла — показывать ошибку пользователю:
```
Ошибка: не удалось записать файл todo.md. Проверьте права доступа.
```

### Инициализация

Если `todo.md` не существует — создать автоматически при первой команде.

---

## Валидация

### Даты

- Формат: только `YYYY-MM-DD` (ISO)
- Дата в прошлом: предупреждение, но создание разрешено
- Невалидная дата: ошибка

### Приоритеты

- Допустимые: `high`, `medium`, `low`
- По умолчанию: не установлен (спросить у пользователя)

### Статусы

- Допустимые: `todo`, `in_progress`, `done`
- По умолчанию: `todo`

## Интеграция с RAG

### Использование

RAG используется для:
1. **Поиск контекста** при `/priority` — блокеры, зависимости из документации
2. **Статус проекта** при `/status` — информация из README, CHANGELOG

### Не используется

Задачи **не индексируются** в Chunkenizer. Чтение только через MCP filesystem.

## Ограничения и tradeoffs

| Решение | Преимущество | Недостаток |
|---------|--------------|------------|
| Один файл todo.md | Простота, легко читать | Не масштабируется >30 задач |
| Last write wins | Нет сложной синхронизации | Возможна потеря данных |
| Нет истории изменений | Простота | Нет аудита |
| Только MCP (без индекса) | Нет зависимости от Chunkenizer для задач | Нет семантического поиска по задачам |
| Обязательный assignee | Чёткая ответственность | Нужно указывать при каждом создании |
| ISO-даты | Однозначность | Менее удобно для пользователя |
